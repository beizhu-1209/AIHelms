# AIHelms — 企业 AI 资源管理平台分析报告

> 分析日期：2026-05-30 | 版本：v0.1.3

## 一、一句话定位

**AIHelms 是一个企业级 AI 资源管理平台**——以 LiteLLM 为 AI 网关底座，为企业提供模型、Skill、MCP Server、智能体的统一纳管、分发、审批和效能分析能力。

---

## 二、核心架构

```
用户/客户端 → Nginx (:80)
                ├── /api → AIHelms Backend (FastAPI + Gunicorn :8000)
                ├── /admin/ → 管理后台 SPA (Vue 3 + TypeScript)
                └── / → 用户端 SPA (Vue 3 + TypeScript)
                              ↓
             平台 DB (PostgreSQL 16) ←→ LiteLLM (AI 网关 :4000)
                              ↓                    ↓
                    Celery Worker + Beat    模型供应商 (OpenAI, Anthropic, DeepSeek...)
```

### 技术栈

| 层 | 技术 |
|---|---|
| 后端 | Python 3.11+, FastAPI, Gunicorn, Celery, SQLAlchemy 2.0 异步 |
| 前端 | Vue 3.4+, TypeScript, Vite 5+, TailwindCSS, npm monorepo (admin / web / shared) |
| AI 网关 | LiteLLM v1.85.1（官方镜像，不做源码修改） |
| 数据库 | PostgreSQL 16，`aihelms` schema 含 41 张业务表 |
| 缓存/队列 | Redis 7（Celery broker + 缓存） |
| 部署 | Docker Compose（5 个服务：db / redis / litellm / aihelms / nginx） |

### 数据流设计原则

- **平台 DB 是唯一数据源（Source of Truth）**：所有业务数据先在平台落表，再同步到 LiteLLM
- **配置数据实时推送**：模型、Key、凭证 → 平台 DB 先写 → 同步 LiteLLM
- **运行时数据定时拉取**：usage、spend、logs → LiteLLM 产生 → Celery 定时拉取存入平台 DB
- **LiteLLM 可独立升级**：只通过 HTTP API 交互，不修改源码、不挂载自定义文件

## 三、功能模块全景

### 1. 🏢 AI 身份（组织与权限管理）

管理企业组织架构和人员的 AI 使用身份。

| 功能 | 说明 |
|---|---|
| **部门管理** | 树形组织架构，支持成员/负责人管理，自动同步为 LiteLLM Team |
| **项目管理** | 扁平项目组，成员管理 |
| **人员管理** | 用户 CRUD，角色/部门/项目多维度归属 |
| **RBAC 权限** | 4 个内置角色（super_admin / admin / department_manager / user），39 个细粒度权限点，支持角色自定义和权限分配 |
| **AI 身份 Key** | 一人可持多个 Key（1 主 Key + N 场景 Key），支持个人/部门/项目三种归属，每个 Key 独立配置模型白名单、MCP/Skill/Agent 权限、预算上限、TPM/RPM 速率限制 |
| **批量操作** | 批量创建 Key、批量更新 Key、批量分配资源 |
| **业务场景** | 资源分类标签（代码开发、客服、数据分析、内容创作、文档处理、翻译、其他） |

### 2. 🤖 模型纳管

统一管理所有 AI 模型供应商、凭证和模型部署。

| 功能 | 说明 |
|---|---|
| **供应商管理** | 支持 17+ 种 AI 供应商：OpenAI、Anthropic、Azure、Google、DeepSeek、Bedrock、Vertex AI、火山引擎、百炼（DashScope）、智谱、Moonshot、MiniMax、vLLM、SGLang、Ollama、LM Studio 及自定义 |
| **凭证管理** | API Key 加密存储，支持 API Base 配置，自动同步到 LiteLLM |
| **模型注册** | 统一模型目录，支持 LLM / Embedding / Rerank / 多模态等多种类别 |
| **模型部署** | 同一模型可挂多个凭证部署，实现负载均衡和容灾 |
| **路由策略** | 全局路由器配置：随机 / 延迟优先 / 成本优先 / 最少繁忙 / 用量优先，支持 fallback 链路、冷却时间、重试次数、超时配置 |
| **发布管理** | 模型可发布到用户端，按部门/用户粒度控制可见性，可选上架审批 |
| **接入测试** | 在线连通性测试，支持 Chat（流式/同步）、Embedding、Rerank |
| **Anthropic 格式** | 自动检测并生成 `/v1/messages` 格式的 Anthropic 兼容端点 |

### 3. 🔌 MCP Server 管理

MCP（Model Context Protocol）Server 的全生命周期管理。

| 功能 | 说明 |
|---|---|
| **Server 注册** | 支持 SSE 和 HTTP 传输协议，多种认证方式（Header、OAuth 等） |
| **工具发现** | 自动连接 MCP Server 解析工具列表和参数 Schema |
| **健康检查** | 手动/定时检测 MCP Server 可用性 |
| **工具级计费** | 每个工具可独立配置计费模式（按次/按月）和价格 |
| **连接配置** | 用户端一键获取连接 JSON（含 API Key 和所有工具信息），直接配置到 Claude Desktop 等本地客户端 |
| **分类管理** | 自定义 MCP 分类（通用、搜索等） |
| **上架审批** | MCP Server 发布需管理员审批，审批通过后用户可见 |

### 4. 🧩 Skill 管理

Skill（AI 技能包）的发布与分发。

| 功能 | 说明 |
|---|---|
| **Skill 发布** | 支持 zip 包上传，名称/版本/描述/图标/分类完整元信息 |
| **安装引导** | 用户获取 Skill 时提供安装说明和 Agent 提示词 |
| **下载管理** | 支持管理员直接下载 zip，用户通过 AI Key 认证下载 |
| **安装统计** | 追踪 Skill 安装/下载次数 |
| **分类管理** | 自定义分类（通用、法律、开发、办公等） |
| **审批流程** | Skill 可配置上架审批，用户申请后管理员审批通过方可使用 |

### 5. 🎯 智能体中心

企业智能体的注册与分发。

| 功能 | 说明 |
|---|---|
| **智能体注册** | 支持 Dify、Coze、自定义等多种平台类型 |
| **平台管理** | 可扩展的智能体平台定义 |
| **使用追踪** | 记录每次智能体调用（用户、时间、智能体），统计用户数和调用量 |
| **成本归属** | 支持按归属人（owner）或使用人（user）两种成本归因模式 |
| **访问方式** | 用户端一键跳转智能体聊天页面，记录使用行为 |
| **分类/Category** | 智能体分类管理 |

### 6. 📊 AI 效能（数据分析中心）

企业 AI 使用的全方位效能分析。

| 维度 | 分析内容 |
|---|---|
| **总览** | AI 覆盖率、总投入（CNY）、人均成本、活跃用户趋势、部门覆盖率排名、人均成本排名 |
| **采纳分析** | 谁在用 AI、使用深度、哪些人还没用过（识别推广目标）、智能体/MCP/Skill 使用排行 |
| **成本分析** | 按部门/用户/模型多维度成本拆解，费用构成饼图，帕累托分析 |
| **预算管理** | Key 级预算使用进度，供应商月度预算执行，超额告警 |
| **效能报告** | AI 自动生成分析报告 + 优化建议，建议可标记处理状态（待处理/已采纳/已忽略） |
| **可视化** | ECharts 图表：趋势图、饼图、帕累托图、热力图、象限图、预算进度条、KPI 卡片 |

### 7. 📝 日志与审计

全链路调用日志和管理操作审计。

| 类型 | 说明 |
|---|---|
| **LLM 调用日志** | 从 LiteLLM SpendLogs 增量同步（5 分钟间隔），反查用户/Key/部署，计算内部成本，支持按时间/用户/模型/供应商/状态筛选 |
| **MCP 调用日志** | 追踪每次 MCP 工具调用，关联用户和 Server |
| **Skill 使用日志** | Skill 下载/安装记录 |
| **Agent 使用日志** | 智能体调用记录 |
| **管理员审计日志** | 所有管理端写操作自动记录（操作人、时间、HTTP 方法、路径、摘要、结果），支持按多维度筛选，详情抽屉展示请求摘要 |
| **日志保留策略** | 管理员日志默认保留 180 天自动清理，LLM 日志可配置保留策略（默认不清理） |

### 8. 🔐 安全

| 功能 | 说明 |
|---|---|
| **双认证模式** | JWT（用户登录）+ API Key（第三方系统集成），API Key 可设置过期时间 |
| **凭证加密** | 供应商 API Key 加密存储，管理端仅密文展示 |
| **Key 安全** | AI Key 仅创建时明文展示一次，后续只能复制掩码后的值 |
| **权限控制** | 39 个细粒度权限点，admin 跳过权限检查，非 admin 需显式授权 |
| **审计中间件** | AuditLogMiddleware 自动捕获所有变更请求的完整上下文 |
| **敏感信息保护** | 日志中不输出密码、Token、Key 等敏感信息 |

### 9. 🛒 用户端（Web Portal）

面向企业员工的 AI 资源自助入口。

| 页面 | 功能 |
|---|---|
| **AI 身份卡** | 个人信息卡：部门/职位、API Key（显示/隐藏/复制）、预算/已用额度、关联资源数量（模型、MCP、Skill），月度消费趋势图，待审批申请列表 |
| **AI 市场** | 浏览已上架 Skill 和 MCP Server，按类型/分类筛选和搜索。可直接获取接入信息（连接 JSON + 工具列表）或提交使用申请 |
| **模型广场** | 浏览已发布模型，按类别和能力筛选。获取连接信息：模型 ID、Base URL、API Key（含 Anthropic 格式变体） |
| **智能体中心** | 浏览可用智能体，按平台/分类筛选。在线智能体一键跳转聊天，需审批的提交申请 |

### 10. 📋 资源审批

统一的资源申请与审批工作流。

- 覆盖模型、MCP Server、Skill、Agent 四种资源
- 用户端提交申请（含申请理由）→ 管理端审批（通过/拒绝 + 审批意见）
- 按状态（待审批/已通过/已拒绝）和资源类型筛选
- 仪表盘待审批事项提醒

## 四、能解决哪些企业问题

| 痛点 | AIHelms 的解决方案 |
|---|---|
| **AI 资源散乱**：多个供应商、多套 Key，各自为政 | 统一纳管所有供应商和模型，一处配置全局生效，自动同步到 LiteLLM 网关 |
| **成本失控**：不知道谁在用、花了多少钱、哪个部门用得最多 | 多维度成本追踪（部门/用户/模型/Key），预算管控 + 超额告警，USD/CNY 自动汇率转换 |
| **安全风险**：API Key 泄露、越权使用、无审计追溯 | 加密凭证存储，RBAC 细粒度权限体系，Key 级资源白名单，TPS/RPM 速率限制，全量操作审计 |
| **资源利用率低**：买了模型没人用，或关键部门不知道有 AI 资源 | AI 效能分析报告识别未使用用户和低覆盖率部门，驱动推广和培训决策 |
| **审批流程缺失**：谁都能拿 Key 随意使用模型，缺乏管控 | 资源申请→审批→授权完整工作流，模型/MCP/Skill/Agent 均可配置上架审批 |
| **MCP/Skill 分发难**：团队自建的 MCP Server 和 Skill 无法在企业内共享 | AI 市场统一上架、分类、审批、安装流程，用户端自助获取接入信息 |
| **运维审计要求**：需要完整的管理操作记录 | 全量管理员操作审计日志，可追溯、可过滤、可自动清理 |
| **供应商切换成本高**：换一个模型供应商要改所有客户端配置 | 模型部署层抽象，同一模型可挂多个凭证，路由策略自动切换（fallback + 冷却 + 重试） |
| **多租户场景**：不同部门/项目组需要不同的 AI 资源配额 | 部门树 + 项目组，Key 按归属隔离，模型可见性按部门/用户粒度控制 |
| **AI 效能不可见**：管理层不知道 AI 投入产出比 | AI 效能分析多维度看板：覆盖率、渗透率、人均成本、部门排名、AI 自动生成优化报告 |

## 五、技术亮点

1. **平台数据为唯一数据源**：所有业务数据先在平台 DB 落表，再同步 LiteLLM。即使 LiteLLM 数据丢失，平台可完整恢复
2. **不修改 LiteLLM 源码**：只通过 LiteLLM HTTP API 交互，LiteLLM 可独立升级
3. **Supervisor 单容器多进程**：Gunicorn + Celery Worker + Celery Beat 三进程统一管理，部署简单
4. **前端 npm monorepo**：admin / web / shared 三包架构，代码复用，admin 和 web 互不依赖
5. **envsubst 模板化 Nginx**：环境变量驱动 Nginx 配置，无需重建镜像
6. **异步全链路**：FastAPI + SQLAlchemy 2.0 async + asyncpg，Celery 后台任务处理耗时操作
7. **流式接入测试**：模型连通性测试支持 SSE 流式输出，模拟真实调用体验
8. **多供应商前缀映射**：40+ 条预置路由前缀规则，覆盖主流国内外 AI 供应商
9. **增量数据同步**：LLM Log 和 MCP Log 通过 SyncState 游标实现增量拉取，避免全量同步
10. **Anthropic 格式智能适配**：自动检测模型部署信息，生成 `/v1/messages` 格式端点供 Claude 客户端使用

## 七、部署架构

### 生产环境

```
docker compose up -d
```

| 服务 | 镜像 | 端口 | 说明 |
|---|---|---|---|
| db | postgres:16-alpine | 内部 | PostgreSQL，含完整建表 + 种子数据 |
| redis | redis:7-alpine | 内部 | Celery broker + 缓存 |
| litellm | docker.litellm.ai/berriai/litellm:v1.85.1 | 4000 | AI 网关，模型配置存储在 DB |
| aihelms | registry.cn-zhangjiakou.aliyuncs.com/microbaton/aihelms | 8000(内部) | 主应用（Gunicorn + Celery Worker + Celery Beat 由 Supervisor 管理） |
| nginx | nginx:latest | 80 | 反向代理 + 静态文件服务 |

### 开发环境

```bash
./dev/setup                    # 首次：复制 .env + 安装依赖
./dev/start-docker-compose     # 启动中间件（db/redis/litellm/nginx）
./dev/start-api                # 启动后端（uvicorn + celery）
./dev/start-web                # 启动前端（Vite admin + web）
```

开发模式下应用代码在宿主机运行，支持热重载。

### 容器内进程管理（Supervisor）

| 进程 | 优先级 | 说明 |
|---|---|---|
| gunicorn | 30（最高） | 生产 WSGI 服务器，多 worker |
| celery-worker | 20 | 异步任务消费 |
| celery-beat | 10 | 定时任务调度 |
